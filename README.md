# Домовой

Чат-бот и мини-приложение в MAX, которые помогают жителю многоквартирного дома понять,
**кто отвечает** за возникшую проблему и **в какой срок** обязан отреагировать.

Решение трека «Умный город», команда 273.

**Чат-бот в MAX:** [@t273_hakaton_max_bot](https://max.ru/t273_hakaton_max_bot)
**Мини-приложение:** https://vyacheslavbelg.github.io/Project-Pennsylvania-/

В MAX бот отображается как «Хакатон МАХ 273» — это имя задано организаторами при выдаче
токена, и на онлайн-этапе оно не меняется. «Домовой» — название продукта.

Реализованы привязка дома, классификатор проблемы, определение зоны ответственности,
нормативный срок с основанием, формирование текста обращения, отсчёт срока и эскалация
в жилищную инспекцию. Мини-приложение — каркас, карточка обращения в работе.

---

## Назначение решения

С 1 сентября 2026 года управляющие организации обязаны взаимодействовать с собственниками
через MAX (ПП РФ от 26.01.2026 № 40). Канал задан законом, но житель по-прежнему не знает
двух вещей: кто отвечает за конкретную проблему — управляющая организация, ресурсоснабжающая
организация, подрядчик или муниципальная служба, — и какой нормативный срок применим.

Сроки заданы разными актами и различаются на порядки: 5 минут на ответ аварийного диспетчера,
3 рабочих дня по качеству коммунальной услуги, 10 рабочих дней по прочим вопросам,
30 календарных дней в общем порядке. Категорию своей проблемы житель не знает, а значит не
знает и срока — и не может заметить, что срок нарушен.

Продукт закрывает этот разрыв: определяет зону ответственности по типу проблемы и
характеристикам дома, показывает применимый норматив с основанием и помогает довести
обращение до результата.

## Основной пользовательский сценарий

1. Пользователь открывает бота в MAX и привязывается к своему дому по адресу.
2. Бот распознаёт адрес по государственному адресному реестру; для домов демонстрационного
   набора показывает управляющую организацию и источник данных.
3. Пользователь выбирает, что случилось: семь категорий на первом экране, внутри — темы,
   уточняющие место и масштаб проблемы.
4. Бот показывает, кто отвечает, нормативный срок с основанием и порядок действий.
   При аварии — сразу телефон аварийной службы, без анкеты.
5. Бот формирует текст обращения. Отправляет его житель сам; с подтверждения отправки
   начинается отсчёт срока.
6. За сутки до истечения срока бот напоминает, при нарушении — собирает жалобу
   в жилищную инспекцию.
7. В «Моих обращениях» — список со статусом и остатком срока, у каждого обращения
   карточка с текстом и действиями.

Все шаги работают в боте. Мини-приложение — каркас, карточка обращения в нём в работе.

## Состав и архитектура решения

| Компонент | Технология | Роль |
|---|---|---|
| `Domovoy.Core` | C#, .NET 10 | Ядро: домен, модель данных, справочники, клиент MAX Bot API |
| `Domovoy.Api` | ASP.NET Core | Хост: чат-бот и REST для мини-приложения в одном процессе |
| `Domovoy.WebApp` | React 19, TypeScript, Vite, MAX UI | Мини-приложение |
| `db` | PostgreSQL 17 | Данные и справочники |

Граница «ядро / переменная часть» проходит по данным, а не по сборкам. В коде — идентификация
дома, роли, механика сценария. В справочниках базы — категории проблем, зоны ответственности,
нормативные сроки, контакты организаций. Чтобы запустить продукт в другом регионе, меняются
строки справочников, а не код.

События от MAX принимаются через long polling. Сценарий получает готовый объект обновления и
не знает, откуда тот пришёл, поэтому переход на вебхук не затронет логику.

## Запуск

```bash
cp .env.example .env     # заполнить MAX_BOT_TOKEN
docker compose up -d --build
```

Одна команда поднимает базу, бэкенд с ботом и мини-приложение.

## Параметры окружения и переменные

| Переменная | Назначение | Обязательна |
|---|---|---|
| `MAX_BOT_TOKEN` | Токен чат-бота, выдан организаторами | да |
| `POSTGRES_PASSWORD` | Пароль базы данных | нет, по умолчанию `domovoy` |
| `MAX_WEBAPP_URL` | Адрес мини-приложения для кнопки в боте | нет |
| `WEBAPP_ORIGINS` | Источники, которым разрешены запросы к API | нет |
| `VITE_API_BASE_URL` | Адрес бэкенда, подставляется в сборку мини-приложения | нет |
| `DADATA_API_KEY` | Ключ DaData для подсказок по адресам из ФИАС | нет, без него поиск только по своей базе |
| `MAX_BIND_FORM` | Кнопка формы выбора дома в боте; включается, когда бэкенд доступен по публичному HTTPS | нет, по умолчанию `false` — адрес вводится сообщением |

Рабочие значения в репозиторий не попадают: `.env` исключён через `.gitignore`.
Шаблон — `.env.example`.

## Зависимости

Версии зафиксированы: `packages.lock.json` для проектов .NET, `package-lock.json` для
мини-приложения, теги базовых образов в Dockerfile.

Ключевые: EF Core 10 и Npgsql — доступ к данным; React 19 и `@maxhub/max-ui` — интерфейс
мини-приложения. Официальной клиентской библиотеки MAX для C# нет, поэтому работа с Bot API
идёт через `HttpClient` напрямую.

## Внешние сервисы и интеграции

| Сервис | Зачем | Нужен для проверки |
|---|---|---|
| MAX Bot API (`platform-api2.max.ru`) | Приём событий и отправка сообщений | да |
| MAX Bridge (`st.max.ru`) | Данные о платформе запуска мини-приложения | да |
| DaData (`suggestions.dadata.ru`) | Подсказки по адресам из ФИАС/ГАР | нет, поиск деградирует до своей базы |
| GitHub Pages | Раздача мини-приложения | да |

Воспроизвести MAX внутри Docker невозможно — это внешняя платформа. Для проверки нужен
доступ к боту по ссылке выше.

**Сертификат.** `platform-api2.max.ru` использует сертификат, выпущенный НУЦ Минцифры. Его
корень не входит в стандартные хранилища, поэтому он добавлен в образ из `docker/certs/`.
Без этого шага соединение с MAX API не устанавливается.

## Работа с данными

| Данные | Статус | Источник |
|---|---|---|
| Адреса домов | **реальные** | ФИАС/ГАР через DaData, подсказки онлайн |
| Категории проблем, зоны ответственности | справочник | составлено по ЖК РФ и правилам предоставления коммунальных услуг |
| Нормативные сроки | справочник | ПП РФ № 354, № 416, № 331 — основание хранится в каждой записи |
| Управляющие организации | **демонстрационные** | подготовленный набор по Казани |

Адрес распознаётся для любого дома России, нормативные сроки федеральные — они тоже
работают везде. Сведения об управляющей организации есть только для подключённых домов;
для остальных продукт прямо сообщает, что данных нет и откуда они появятся.

Каждая запись несёт поля происхождения: источник, наименование, дата актуальности, территория.
Эти данные показываются пользователю вместе с результатом.

Интеграции с ГИС ЖКХ нет: её API выдаётся только организациям — управляющим, ТСЖ и
ресурсоснабжающим. Поэтому сведения об управляющих организациях демонстрационные, и это
помечено и в интерфейсе, и в ответах API — требование ТЗ не имитировать интеграции.

## Порядок работы с тестовыми данными

Справочники и демонстрационные дома загружаются автоматически при старте `api`, после
применения миграций. Повторный запуск данные не дублирует.

Ввести можно **любой адрес России** — он распознаётся по государственному адресному реестру.
Полная карточка с управляющей организацией доступна для подготовленных домов в Казани:

```
Баумана 15, Баумана 17, Профсоюзная 23,
Ямашева 54, Ямашева 56, Чистопольская 78, Декабристов 112
```

Для остальных адресов бот сообщает, что сведений об управляющей организации нет, и объясняет,
откуда они появляются.

## Пошаговый сценарий проверки

1. `cp .env.example .env`, вписать `MAX_BOT_TOKEN`.
2. `docker compose up -d --build`, дождаться готовности.
3. Проверить бэкенд: `curl http://localhost:8080/health` → `{"status":"ok"}`.
4. Открыть в MAX бота [@t273_hakaton_max_bot](https://max.ru/t273_hakaton_max_bot),
   отправить `/start`.
5. Нажать «Привязать дом», ввести `Баумана 15`, выбрать дом.
6. «Сообщить о проблеме» → «Вода, отопление, электричество» → «Холодно у меня и у соседей».
7. Бот показывает разбор. Нажать «Без описания».
8. Бот показывает текст обращения. Нажать «Я отправил обращение» — начинается отсчёт.
9. «Мои обращения» → номер обращения: карточка со сроком, текстом и действиями.
10. «‹ Главное меню» → «Сообщить о проблеме» → «Авария или опасность»: сразу экран
    аварийной службы, без вопросов.

## Примеры ожидаемого поведения системы

На шаге 5 приходит карточка дома:

```
Дом привязан.

🏠 Республика Татарстан, Казань, ул. Баумана, д. 15
Управление: ООО УК «Жилищник Вахитовского района»
Телефон: +7 843 000-00-01
Аварийная служба: +7 843 000-00-11
Способ управления: управляющая организация
Год постройки: 1968

Источник: демонстрационные данные, на 20 сентября 2026
```

На шаге 7 — разбор:

```
Отвечает: Управляющая организация

Проблема общедомовая: внутридомовая система отопления относится к общему имуществу,
и отвечает за неё управляющая организация.
Основание: ПП РФ от 06.05.2011 № 354; ПП РФ № 491

Нормативный срок: 3 раб. дн.
Основание: ПП РФ от 06.05.2011 № 354
Ответ должен поступить до <через 3 рабочих дня от момента проверки>
```

Если ввести адрес за пределами подготовленного набора — например, «Казань Жуковского 2», —
бот распознает его по адресному реестру и прямо сообщит, что данных об управляющей
организации нет. Разбор, срок и обращение при этом работают: эти правила федеральные.

Мини-приложение на http://localhost:8081 показывает список домов и данные MAX Bridge.
Вне мессенджера в поле платформы отображается «вне MAX» — Bridge работает только внутри MAX.

## Известные ограничения

- **Обращение не доставляется в систему управляющей организации** — канала в их системы нет.
  Продукт формирует корректное обращение и определяет адресата; отправляет житель сам.
- Сведения об управляющих организациях демонстрационные. Открытого источника связки
  «дом → управляющая организация» не существует: API ГИС ЖКХ выдаётся только организациям.
  Адреса при этом реальные — из государственного адресного реестра.
- Принадлежность пользователя к дому не проверяется: в MVP привязка принимается на слово.
- События принимаются через long polling, а не вебхук: публичный адрес появится вместе
  с прод-хостингом. Одновременно опрашивать может только один экземпляр приложения.
- Действие от имени пользователя в API одно — привязка дома из формы мини-приложения.
  Пользователь определяется только по `initData`, подписанному платформой: подпись
  проверяется на бэкенде по HMAC-SHA256 от токена бота. Форма включается переменной
  `MAX_BIND_FORM`, когда бэкенд доступен по публичному HTTPS; до того адрес вводится
  сообщением в чат.
- Сообщения, которые пользователь пишет в чат сам, бот удалить не может: в личном
  диалоге MAX на это отвечает 403. Поэтому ввод адреса вынесен в форму.
- Справочник проблем — 7 категорий и 26 тем — составлен по каталогу
  [docs/product/08-problem-catalog.md](docs/product/08-problem-catalog.md) на основе
  официальных примеров заявок «Госуслуги Дом». Сопоставление тем с зоной ответственности
  и нормативом — вывод команды по ЖК РФ и постановлениям Правительства, а не юридическое
  заключение: граница ответственности зависит ещё от договора управления и местной схемы.
- Направления «Жилищный навигатор» и «Домовое сообщество» сознательно не реализуются.

## Остановка и повторный запуск

```bash
docker compose down        # остановить, данные сохраняются в томе
docker compose up -d       # запустить снова
```

Полный сброс вместе с данными:

```bash
docker compose down -v
```
