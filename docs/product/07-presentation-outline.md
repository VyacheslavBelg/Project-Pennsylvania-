# Структура презентации

**Статус:** ⬜ не заполнено · **Срок:** Фаза 5 (28—30.09) · **Отвечает:** Никита

Требования — стр. 10 PDF ([../tz/05-submission-format.md](../tz/05-submission-format.md)).
Критерий «Качество презентации решения» — 5% продуктовой оценки (2% итога), но **отсутствие
презентации обнуляет всё решение** ([../checklists/01-admission.md](../checklists/01-admission.md)).

> ТЗ: «Структура презентации может отличаться, однако материалов должно быть достаточно для
> продуктовой оценки». Порядок ниже следует рекомендованному в ТЗ.

---

## Слайд 1 — служебный

> Не оценивается в рамках продуктовой презентации. Данные используются только для технической
> проверки решения.

- [ ] Ссылка на работающего чат-бота или мини-приложение в MAX
- [ ] Ссылка на Git-репозиторий **и commit hash**
- [ ] Адрес собственного API — если используется
- [ ] Тестовые логины и пароли
- [ ] Рабочие токены, API-ключи и другие значения переменных окружения, необходимые для запуска
      и проверки
- [ ] Краткий порядок прохождения основного пользовательского сценария

Это единственное место, где передаются секреты: в репозиторий их класть нельзя (ограничение 8),
сюда — нужно.

«Краткий порядок прохождения» — не ссылка на README, а 3–5 строк прямо на слайде. Проверяющий
должен пройти сценарий, не открывая репозиторий.
