## Что изменилось после исследования

1. Полный legal/competitor review показал, что «Госуслуги Дом» уже закрывает больше функций, чем предполагалось в ранних продуктовых документах.
2. Нельзя считать текущую гипотезу «routing до правильного исполнителя» автоматически финальной только потому, что под неё создано доменное ядро.
3. Сильный кандидат для следующей проверки — переход `официальное известное событие → понять, нужно ли действовать → после истечения срока перейти к следующему официальному шагу`.
4. Это пока гипотеза, а не утвержденный pivot.

## Что НЕ менять до decision gate

- не выбрасывать существующее доменное ядро;
- не строить новый кабинет УК;
- не добавлять рейтинг/голосования/новости как отдельные продуктовые модули;
- не расширять классификатор только ради количества категорий;
- не заявлять реальную интеграцию с ГИС ЖКХ без доступа;
- не переписывать архитектуру под гипотезу, которая ещё не проверена.

## Следующий gate

Перед обновлением product scope команда должна получить:

- дополнительные интервью;
- walkthrough официального продукта;
- UX-проверку сценария с известным событием/ETA;
- сравнительную матрицу H1–H5;
- одно решение: какой именно пользовательский переход становится ядром MVP.

После gate обновляются `docs/product/01..04`, затем только необходимые части архитектуры/кода.
