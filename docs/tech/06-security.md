## Секреты

**Ограничение 8: нельзя размещать в репозитории рабочие токены, пароли, API-ключи и другие
секреты.**

### Правила

- [ ] `.env` в `.gitignore` — **добавить до первого коммита с конфигурацией**
- [ ] `.env.example` содержит только плейсхолдеры
- [ ] Токен бота хранится вне git; место: ______________
- [ ] Никаких секретов в `appsettings.json`, в коде, в CI-конфигах, в комментариях
- [ ] Скриншоты в README и презентации не содержат реальных токенов

### Асимметрия, которую важно не перепутать

| Куда | Секреты |
|---|---|
| Репозиторий | ❌ запрещено |
| Служебный слайд презентации | ✅ **обязательно** — это единственный канал передачи проверяющим |

### Проверка истории git

Подпункт критерия: «рабочие токены, пароли, ключи и другие секреты **не размещены в исходном
коде**». Проверяется вся история, а не текущее состояние.

```bash
# поиск по всей истории
git log -p --all | grep -iE "token|password|secret|api[_-]?key" | head -50
git log --all --diff-filter=A --name-only | grep -iE "\.env$|secrets"
```

- [ ] Прогнано, дата: ________
- [ ] Если секрет попал в историю — **токен отозван и перевыпущен**, а не просто удалён коммитом

Удаление файла новым коммитом не убирает секрет из истории. Порядок действий: отозвать токен
у организаторов, перевыпустить, и только потом чистить историю.

## Зависимости

Подпункт: «зависимости и их версии зафиксированы».

- [ ] `packages.lock.json` включён (`RestorePackagesWithLockFile`) и закоммичен
- [ ] `package-lock.json` закоммичен, не в `.gitignore`
- [ ] Версии базовых Docker-образов зафиксированы тегами, не `latest`
- [ ] Нет зависимостей из непроверенных источников

### Лицензии — ограничение 7

> Запрещено использование закрытых библиотек, частных API и чужого кода, не подпадающего под
> разрешение о свободном распространении и использовании.

- [ ] Все библиотеки — с открытыми лицензиями, допускающими использование
- [ ] Скопированный откуда-либо код имеет совместимую лицензию и указан источник
- [ ] Иконки, шрифты, изображения в мини-приложении и презентации — с правом использования

| Библиотека / ресурс | Лицензия | Проверено |
|---|---|---|
| | | ⬜ |

## Доступ к данным

Подпункт: «доступ к данным соответствует логике решения».

| Вопрос | Ответ |
|---|---|
| Может ли пользователь получить данные чужого дома? | |
| Как проверяется, что пользователь привязан к дому? | |
| Разграничены ли права ролей (житель / председатель / сотрудник УК)? | |
| Валидируются ли данные пользователя, пришедшие из мини-приложения, на бэкенде? | |

- [ ] Запросы к API мини-приложения авторизуются на бэкенде, а не «доверяют» фронту
- [ ] Идентификатор пользователя из MAX проверяется, а не принимается на веру из параметра
- [ ] Прямой перебор идентификаторов не даёт доступа к чужим данным

Для MVP допустимы упрощения, но они должны быть заявлены в блоке ограничений
([../product/03-mvp-scope.md](../product/03-mvp-scope.md)). Заявленное упрощение — решение,
незаявленная дыра — «очевидный критичный риск безопасности» по формулировке критерия.
