## Реестр источников

Каждая строка обязана иметь честный статус. Ограничение 10 ТЗ: если используются тестовые,
заранее подготовленные или смоделированные данные, это должно быть **явно указано в
материалах**.

| Источник | Что берём | Статус в MVP | Актуальность | Что нужно для реальной интеграции |
|---|---|---|---|---|
| ФИАС / ГАР (ФНС) | адреса, идентификация дома | ☑ **реальная** — через DaData | подсказки онлайн | — |
| ГИС ЖКХ | дом, УК, капремонт, работы | ☑ **недоступна** | — | API выдаётся только организациям: УК, ТСЖ, РСО |
| Росстат | статистика жилфонда — для обоснования, не в продукте | справочно | 2024 | — |
| Нормативные сроки и правила | сроки рассмотрения, зоны ответственности | ⬜ справочник в БД | | |
| Данные УК | реестр помещений, контакты | ☑ тестовые | 20.09.2026 | договорённость с пилотной УК |

**Легенда статусов:**
- **реальная** — живой вызов внешней системы в рантайме
- **выгрузка** — официальные данные, загруженные заранее, обновляются вручную
- **тестовые** — синтетические или обезличенные подготовленные данные

## Проверка источников связки «дом → УК»

Проведена 20.09.2026. Открытого источника нет — это факт, а не предположение.

| Источник | Результат проверки |
|---|---|
| ГИС ЖКХ | REST API выдаётся только организациям — УК, ТСЖ, РСО. Третьим лицам доступ не предоставляется |
| HouseScore | платный, 100 пробных запросов, **происхождение данных не раскрывает** |
| Яндекс.Карты | геокодирование: возвращает координаты, сведений об управляющей организации нет в принципе |

Третья строка важна отдельно: геокодер решает другую задачу. Адрес и управляющая
организация — разные данные из разных систем, и подменить одно другим нельзя.

Вторая строка дисквалифицирует HouseScore для нашего продукта: он построен на том, что
у каждого факта есть источник и дата актуальности, а сервис источник не называет. Это
противоречит принципу «используйте первоисточник».

## Как разделены данные

| Что | Источник | Покрытие |
|---|---|---|
| Адрес и идентификатор дома | ФИАС/ГАР через DaData | вся Россия |
| Нормативные сроки | федеральные акты | вся Россия |
| Управляющая организация, контакты | ГИС ЖКХ либо партнёрская УК | только подключённые регионы |

Это ровно граница «ядро / переменная часть». Пользователь из любого региона получит
распознанный адрес и применимый норматив; сведения об управляющей организации появляются
там, где регион подключён. Продукт сообщает об этом прямо, а не делает вид, что данных нет
по техническим причинам.

## Не имитируем интеграции

> Принцип 4 ТЗ: «Если у вас нет доступа к реальной информационной системе, используйте
> тестовые, синтетические или заранее подготовленные данные. В материалах явно укажите, какие
> интеграции являются модельными и что потребуется для их реализации после MVP».

**Что это значит практически:**

- ❌ Экран, который выглядит как живая интеграция с ГИС ЖКХ, но питается фикстурами
- ✅ Экран на фикстурах с пометкой источника прямо в интерфейсе
- ❌ «Интеграция с ГИС ЖКХ» на слайде архитектуры, если её нет
- ✅ «Данные ГИС ЖКХ — подготовленная выгрузка; для реальной интеграции нужен статус оператора»

Если данные не из живого вызова: в UI стоит пометка, в README — раздел «порядок работы
с тестовыми данными», на слайде «данные и интеграции» — фактический статус.

## Если используем LLM

> Принцип 5 ТЗ. Применимо, если модель работает с нормативными документами, требованиями или
> другой критичной информацией.

- [ ] Ответы привязаны к источникам
- [ ] Показывается основание для ответа
- [ ] Предусмотрена ситуация, когда надёжного ответа недостаточно — есть путь «не знаю → вот
      куда обратиться», а не выдуманный ответ
- [ ] Предположение модели не выдаётся за официальный факт или требование

Ответ без ссылки на основание в теме нормативки хуже, чем отсутствие ответа.
