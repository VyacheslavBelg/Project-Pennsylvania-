## Состав `compose.yaml`

| Сервис | Образ / сборка | Порт | Зависит от |
|---|---|---|---|
| `api` | `src/Domovoy.Api/Dockerfile`, контекст — корень | 8080 | `db` (healthy) |
| `web` | `src/Domovoy.WebApp/Dockerfile`, nginx со статикой | 8081 | `api` |
| `db` | `postgres:17-alpine` | 5432, наружу не публикуется | — |

- [x] Версии базовых образов зафиксированы тегами, не `latest`
- [x] `depends_on` + healthcheck: `api` не стартует раньше готовности БД
- [x] Миграции БД применяются автоматически при старте
- [x] Тестовые данные загружаются автоматически при старте
- [x] Всё поднимается **одной командой**

**Команда запуска:** `docker compose up -d --build`

## Переменные окружения

Полный список идёт в README (требование формата сдачи: «необходимые параметры окружения»,
«переменные окружения», «используемые порты»).

| Переменная | Назначение | Обязательна | Значение в `.env.example` |
|---|---|---|---|

| `VITE_API_BASE_URL` | адрес бэкенда, подставляется в сборку фронта | нет | пусто до задачи 0.5 |

- [x] `.env` в `.gitignore`
- [x] В `.env.example` только плейсхолдеры, ни одного рабочего значения
- [x] Каждая переменная описана в README

## Внешние сервисы вне Docker

> ТЗ: «Если для работы MVP необходим внешний сервис, который невозможно воспроизвести внутри
> Docker, отдельно укажите его назначение и условия, необходимые для проверки решения».

| Сервис | Зачем нужен | Что нужно проверяющему |
|---|---|---|
| MAX (мессенджер) | среда работы продукта | доступ к боту по ссылке со служебного слайда |
| MAX Bot API | приём событий и отправка сообщений | корневой сертификат Минцифры в образе |
| MAX Bridge (`st.max.ru`) | данные о платформе запуска мини-приложения | доступ в интернет у клиента |

Контейнеризация не заменяет работающую версию продукта в MAX: бот и мини-приложение должны
оставаться доступны для прохождения основного сценария независимо от того, поднял ли
проверяющий Docker.
