### Ник чат-бота

**Ограничение 11 ТЗ: после создания бота ник изменить нельзя.**

Бот создан организаторами. Фактические данные получены запросом `GET /me` 19.09.2026:

| | |
|---|---|
| Ник | `@t273_hakaton_max_bot` |
| Отображаемое имя | «Хакатон МАХ 273» |
| `user_id` | `426401986` |
| Прямая ссылка на мини-приложение | `https://max.ru/t273_hakaton_max_bot?startapp=<payload>` |

При самостоятельной регистрации платформа генерирует ник по шаблону `idИНН_bot` или
`se(orgid)_bot`. Выданный нам ник шаблону не соответствует — организаторы заводили ботов по
своей схеме, по номеру команды.

**«Домовой» — это название продукта, а не имя бота в MAX.** Отображаемое имя сейчас «Хакатон
МАХ 273» и меняется в кабинете платформы, доступа к которому у команды нет. Пока имя не
изменено, название «Домовой» живёт в мини-приложении, в текстах бота и в презентации.

- [ ] Спросить организаторов, могут ли они сменить отображаемое имя бота на «Домовой»
- [ ] Спросить, можно ли зарегистрировать наш адрес для кнопки `open_app`

### Кнопка открытия мини-приложения

Проверено 20.09.2026 перебором вариантов:

| Вариант | Ответ платформы |
|---|---|
| `open_app` без `web_app` | 400, `Field 'webApp' cannot be null` |
| `open_app` + адрес на GitHub Pages | 404, `Link not found` |

ссылка, её и используем.

## Bot API

Сверено с dev.max.ru/docs 18.09.2026.

| | |
|---|---|
| Базовый адрес | `https://platform-api2.max.ru` |
| Авторизация | заголовок `Authorization: <token>` |
| Лимит | 30 запросов в секунду |
| Коды ответов | 200, 400, 401, 429, 503 |

Токен переехал из query-параметра в заголовок `Authorization`. Примеры из сторонних статей,
где токен передаётся через `?access_token=`, устарели.

### Получение обновлений

| Способ | Как | Когда |
|---|---|---|
| Webhook | `POST /subscriptions` регистрирует HTTPS-адрес | прод, рекомендован документацией |
| Long polling | `GET /updates` | только разработка, ограничен по скорости и времени хранения событий |

### Основные методы

| Метод | Эндпоинт | Назначение |
|---|---|---|
| POST | `/messages` | отправка сообщения: текст, вложения, клавиатуры |
| GET | `/messages/{messageId}` | получение сообщения |
| PUT | `/messages/{messageId}` | редактирование |
| DELETE | `/messages/{messageId}` | удаление |
| POST | `/subscriptions` | регистрация вебхука |
| GET | `/subscriptions` | список вебхуков |
| GET | `/chats/{chatId}/members` | участники чата |
| GET | `/me` | информация о боте |

### Клавиатуры и разметка

Инлайн-клавиатура: до 210 кнопок, 30 рядов, не более 7 кнопок в ряду.

Типы кнопок: `callback`, `link`, `request_contact`, `request_geo_location`, `message`,
`clipboard`.

Форматирование текста: `format: "markdown"` или `format: "html"` — жирный, курсив,
зачёркнутый, блоки кода.

### Клиентские библиотеки

Официальные библиотеки есть только для **JavaScript** (`@maxhub/max-bot-api`) и **Golang**.
Библиотеки для C# нет — бэкенд работает с REST напрямую через `HttpClient`.

## Мини-приложение

| Требование | Значение |
|---|---|
| Протокол | HTTPS обязателен |
| Длина URL | не более 1024 символов |
| Символы в адресе | латиница, цифры, точки, дефисы; пробелы запрещены |
| Хостинг из документации | VK Cloud, GitHub Pages, Yandex Cloud |

Мини-приложение работает только внутри чат-бота и не может существовать автономно — совпадает
с ограничением 5 ТЗ.

### Привязка к боту

Адрес мини-приложения прописывается **в настройках бота в кабинете платформы MAX для бизнеса**,
там же выбирается тип кнопки запуска: Open, Start, Play или без названия.

Запуск пользователем: кнопка в интерфейсе чата либо прямая ссылка
`https://max.ru/<botName>?startapp=<payload>`, где payload не длиннее 512 символов.

Доступа к кабинету у команды нет — адрес прописывают организаторы по форме, см. «Регистрация
мини-приложения» выше.

### MAX Bridge

Подключение через CDN:

```html
<script src="https://st.max.ru/js/max-web-app.js"></script>
```

Глобальный объект `window.WebApp`, отдельная инициализация не нужна.

| Метод | Что даёт |
|---|---|
| `initData` | стартовые параметры строкой в URL-кодировке — для проверки на бэкенде |
| `initDataUnsafe` | те же параметры разобранным JSON — **для серверной валидации не годится** |
| `platform` | ios, android, desktop, web |
| `version` | версия приложения |
| `deviceName` | устройство и ОС |

Дополнительно: управление экраном, скачивание файлов, сканирование QR, биометрия, NFC,
тактильная отдача. Методы возвращают Promise.

### Валидация данных на бэкенде

Проверка подлинности пользователя — HMAC-SHA256. Реализуется на C#, готовой библиотеки нет.

1. Взять параметры из фрагмента URL после `#`.
2. Разобрать `WebAppData` в пары `key=value`.
3. Сохранить `hash` и исключить его из обработки.
4. URL-декодировать значения.
5. Отсортировать пары по ключам.
6. Собрать строку `launch_params` вида `key1=value1\nkey2=value2`.
7. `secret_key = HMAC-SHA256("WebAppData", BOT_TOKEN)`.
8. `signature = HMAC-SHA256(secret_key, launch_params)`.
9. Перевести в hex.
10. Сравнить с `hash`.

Без этой проверки идентификатор пользователя из мини-приложения принимать нельзя — см.
[06-security.md](06-security.md), раздел «Доступ к данным».

## Корневой сертификат Минцифры

`platform-api2.max.ru` отдаёт цепочку:

```
CN=*.max.ru, O=MAX LLC
  └─ Russian Trusted Sub CA
       └─ Russian Trusted Root CA   (Минцифры России)
```

Этого корня нет в стандартном хранилище доверенных сертификатов Windows. Проверено 18.09.2026:
запрос к API с машины разработчика падает с `SEC_E_UNTRUSTED_ROOT`.

Следствия:

- на каждой машине разработчика нужно установить корневой сертификат НУЦ Минцифры
  (gosuslugi.ru, раздел с сертификатами);
- то же самое нужно в Docker-образе бэкенда, иначе `HttpClient` не достучится до API из
  контейнера;
- то же самое на прод-сервере, если он не в российском облаке с предустановленным корнем.

- [ ] Сертификат установлен на машинах разработчиков
- [ ] Сертификат добавлен в Dockerfile бэкенда
- [ ] Проверено, что из контейнера проходит запрос `GET /me`

## Схема окружений

| Окружение | Адрес | HTTPS | Назначение |
|---|---|---|---|
| Локальная разработка | туннель | да, от туннеля | отладка |
| Прод (для сдачи) | | да | **адрес, который попадёт в презентацию** |

Туннель не годится как адрес для сдачи: он умрёт вместе с ноутбуком разработчика, а решение
должно быть доступно весь период проверки. Прод-адрес и сертификат — задача Фазы 0.

### Что означает «полный HTTPS-адрес, доступный в течение периода проверки»

Формулировка из формата сдачи. Разбирается на два требования.

**Полный адрес** — абсолютный URL со схемой, по которому можно постучаться сразу, без
уточнений: `https://domovoy-273.ru/api`, а не `domovoy-273.ru`, не IP и не «спросите у нас».

**Доступный в течение периода проверки** — адрес обязан отвечать всё время, пока жюри смотрит
решение, а не только в момент сдачи. Отсюда следует, что не подходят:

| Не подходит | Почему |
|---|---|
| `localhost`, адрес в локальной сети | недоступен извне |
| Туннель (ngrok, cloudflared) | живёт, пока запущен ноутбук, адрес меняется |
| Бесплатный хостинг, засыпающий без трафика | первый запрос жюри упрётся в холодный старт или в ошибку |
| Домен или сертификат с истекающим сроком | проверка может прийтись на день после истечения |

Период проверки точно не известен: он начинается после дедлайна 30.09 и для финалистов тянется
минимум до защиты 29.10. Закладываем доступность **до конца ноября** с запасом.

### Наш сертификат должен быть публично доверенным

Отдельный момент, который легко перепутать. Корень Минцифры нужен **нам**, чтобы ходить в API
MAX. Но сертификат **нашего** сервиса должен быть выпущен общедоверенным центром — Let's Encrypt
или аналогом.

Если выпустить свой сертификат через НУЦ Минцифры, мини-приложение не откроется у всех, у кого
этот корень не установлен, — в том числе, возможно, у жюри. Мы сами только что прошли через эту
ошибку с API MAX.

### Разделение хостинга

Бэкенду и фронтенду нужны разные вещи:

| Компонент | Что нужно | Варианты |
|---|---|---|
| Мини-приложение (статика React) | HTTPS, отдача файлов | GitHub Pages, VK Cloud, Yandex Cloud — все три названы в документации MAX |
| Бэкенд C# и БД | постоянно работающий процесс, домен, TLS | VPS: Timeweb, Selectel, VK Cloud, Yandex Cloud |

Статику можно разместить бесплатно, платить нужно за сервер под бэкенд.

- [ ] Домен зарегистрирован
- [ ] Сертификат выпущен публично доверенным CA, автопродление настроено
- [ ] Хостинг оплачен минимум до конца ноября
- [ ] Адрес отвечает с чужой сети, а не только из дома

## Кандидаты на платформенный бонус (+0,15 балла)

> Начисляется **только целиком**. Условие входа: основной пользовательский сценарий полностью
> работает и доступен для проверки. Возможность должна создавать пользовательскую ценность,
> быть **органично встроена** в продукт, работать от начала до результата и быть описана
> в материалах.
>
> Не является основанием: наличие собственного API, дополнительное число функций, базовые
> обязательные возможности.

Кандидаты по итогам сверки 18.09.2026 — возможности MAX Bridge и Bot API сверх базовой отправки
сообщений. Ценность заполняется после выбора приоритетного сценария:

| Возможность MAX | Какую ценность даёт пользователю | Трудоёмкость | Берём |
|---|---|---|---|
| Сканирование QR (Bridge) | привязка к дому по QR в подъезде вместо ввода адреса | средняя | ⬜ |
| Геолокация (`request_geo_location`) | определение дома по местоположению | низкая | ⬜ |
| `request_contact` | подтверждение телефона при обращении в УК | низкая | ⬜ |
| Биометрия (Bridge) | защита персональных данных в карточке дома | средняя | ⬜ |
| NFC (Bridge) | метка на оборудовании для заявки по месту | высокая | ⬜ |
| Тактильная отдача (Bridge) | отклик на действия в мини-приложении | низкая | ⬜ |

Бонус берём только после того, как приоритетный сценарий закрыт полностью: 0,15 балла не стоят
риска провалить критерий весом 18%.
