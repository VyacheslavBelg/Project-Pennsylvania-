## Что даёт платформа

> MAX позволяет создавать чат-ботов и подключать к ним мини-приложения. Мини-приложения
> работают внутри MAX и расширяют функциональность платформы.

Для разработки доступны:

- **API чат-ботов** — для программной реализации сценариев.
- **Конструкторы сценариев ботов**, которые позволяют запускать чат-ботов без самостоятельной
  разработки и программирования.
- **MAX Bridge** — библиотека, с помощью которой мини-приложение может взаимодействовать с API
  MAX и API устройства пользователя. Она позволяет получать информацию о платформе запуска
  (например, iOS, Android, desktop, web) и адаптировать поведение приложения.
- **MAX UI** — библиотека React-компонентов для разработки интерфейсов мини-приложений в
  стилистике MAX.

> Мини-приложения работают на базе стандартных веб-технологий: **HTML, JavaScript и CSS**.
> Для подключения мини-приложения к MAX оно должно работать по защищённому соединению **HTTPS**.

## Чат-бот или мини-приложение: как выбрать

> До начала разработки определите, какая часть сценария лучше работает в чате, а какая требует
> отдельного интерфейса.

### Чат-бот подходит, если пользователь:

- отвечает на несколько последовательных вопросов;
- выбирает вариант из небольшого количества опций;
- получает персональный результат или рекомендацию;
- проверяет статус;
- получает уведомление или напоминание;
- регулярно выполняет короткое действие.

### Мини-приложение оправданно, если пользователю нужно:

- заполнить более сложную форму;
- работать с большим количеством параметров;
- сравнивать несколько объектов;
- работать со списком или каталогом;
- возвращаться к ранее введённым данным;
- одновременно видеть несколько связанных элементов;
- работать со сложным визуальным интерфейсом.

## Документация и токен

> Документация MAX развивается и обновляется. Перед началом разработки и перед сдачей решения
> **обязательно сверяйтесь с актуальной документацией и историей изменений API**, а не
> ориентируйтесь на старые примеры или инструкции из сторонних источников.
>
> В рамках проведения хакатона токен чат-бота предоставляется организаторами.

**Документация:** https://dev.max.ru/docs

## Разбивка сценария

| Часть сценария | Где реализуем | Почему |
|---|---|---|
| Вход, привязка к дому, уведомления, проверка статуса | **чат-бот** | последовательные вопросы, короткие регулярные действия, статус |
| Карточка дома, списки работ и документов, сравнение, формы | **мини-приложение** | каталог, много параметров, возврат к введённым данным |

Два требования, которые легко пропустить:

1. **HTTPS обязателен** для подключения мини-приложения. Это влияет на схему локальной
   разработки (нужен туннель) и на то, где хостится фронт.
2. **Документация меняется.** ТЗ просит сверяться с историей изменений API перед сдачей,
   а не только в начале. Сверка стоит в плане дважды: Фаза 0 и Фаза 5.

Существование конструкторов сценариев означает, что бот, собранный без кода, не даёт
преимущества на фоне других команд. Дифференциация — в логике, данных и мини-приложении.
