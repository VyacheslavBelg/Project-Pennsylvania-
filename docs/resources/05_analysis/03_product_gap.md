# Product gap после проверки официального контура

## Уже закрыто официальными продуктами

- создание заявки;
- адресаты УО/ТСЖ/РСО/ГЖИ в предусмотренных сценариях;
- номер/статус/ответ;
- официальный чат дома;
- рейтинг/аналитика УО;
- новости и важные события;
- плановые отключения горячей воды;
- показания счетчиков;
- голосования и отчетность.

## Где еще есть пространство для MVP

### 1. Preflight «нужно ли действовать?»
Человек описывает симптом. Домовой сначала проверяет, есть ли уже официальное известное событие и ожидаемый срок восстановления.

### 2. Переход «информация → действие»
Если официальный срок закончился, пользователь не ищет заново нужный раздел/организацию: Домовой переводит контекст события в следующий официальный шаг.

### 3. Provenance UI
Каждый факт помечается как:
- официальный источник;
- сигнал жителей;
- вычисление продукта;
- рекомендация;
- модельные данные MVP.

### 4. Оперативность
Не обещать, что наши данные «свежее ГИС ЖКХ». Ценность — быстро донести доступное официальное состояние и явно показать его время обновления.

### 5. Для УО
Вместо еще одного CRM можно дать слой снижения повторных запросов: одно известное событие → уведомление многих жителей → меньше одинаковых обращений/звонков.
