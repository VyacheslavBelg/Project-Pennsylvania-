# Как государство фактически видит MAX в ЖКХ

По связке ПП РФ № 40 + Приказ Минстроя № 856/пр + ГИС ЖКХ модель выглядит так:

```text
Житель / собственник
        ↓
MAX = интерфейс и канал взаимодействия
        ↓
интеграция
        ↓
ГИС ЖКХ = официальный информационный контур
        ↓
УО / ТСЖ / РСО / ГЖИ / иные участники
```

## Что законодатель прямо поддерживает

1. УО должна обеспечить взаимодействие с жителями в том числе через многофункциональный сервис.
2. Через сервис возможна запись на прием.
3. Приказ № 856/пр вводит электронное взаимодействие и непрерывный доступ к контактной и части оперативной информации.
4. Для РСО прямо названа информация о перерывах в поставках ресурсов.
5. Обращения, показания и ответы в рамках установленного взаимодействия проходят через ГИС ЖКХ.
6. MAX-интеграция строится поверх/через ГИС ЖКХ.

## Что это подсказывает для Домового

Лучше не создавать отдельную «альтернативную государству систему заявок». Сильнее выглядит UX-слой над официальным процессом:

- быстро понять состояние дома;
- показать официальный источник и время обновления;
- отличить известное событие от новой проблемы;
- не плодить ненужное обращение;
- когда действие нужно — довести до официального маршрута;
- после истечения срока — подсказать следующий допустимый шаг.

## Один сильный сценарий MVP

`нет воды → проверка известного события → источник + ETA → напоминание после ETA → проблема осталась → формирование/маршрут официального обращения`.

Для хакатона интеграция с ГИС ЖКХ может быть модельной только при явной маркировке этого факта.
